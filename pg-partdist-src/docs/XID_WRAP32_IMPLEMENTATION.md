# 32 位分片 XID 回卷：实现与验收

实现基于 f74df49，按已确认的冻结与半圈清理方案保持 uint32 分片事务号。
2026-10-29 已在 147 的独立实验数据库完成下列验证。源码在 yyt 副本开发，
验收后同步 VACU 工作区；原实验的安装库与数据库没有被替换。

## 已确认的方案

分片 XID、发号水位、认领水位、两条清理水位与 clog 槽号保持 uint32。
不增加事务轮次，不拼接扩展 XID。行头仍使用 PostgreSQL 的 32 位 XID。
先把安全的老 xmin 显式冻结，消毒中止 xmax，清理中止插入和提交删除；
完整清理并持久复制后才能回收号码。未回收区间严格小于半圈，启动线早于
停发线。旧快照、活跃事务、尚未闭合的准备事务或决议阻挡安全清理时，
只停止该分片继续发号。

## 代码落实

- `shard_xid_math.h` 集中处理 uint32 模距离、区间、跨零和跳过 0/1/2。
- 发号按回收点计算余量，不再以 0xFFFF0000 为绝对停发点。
- 为一批新号授权之前，先清零相应旧 clog 槽并 fsync，再持久化授权水位。
- 水位文件增加格式版本、校验和和清理完成位置。崩溃恢复补完已公布但未完成的
  槽清理；部分页面清理仍按原两态方案整趟重跑。
- 普通号码的终局判决不再永久缓存在连接中；号码复用后必须重新查真实账本。
- 原生活跃表保留准备事务直到 COMMIT/ROLLBACK PREPARED 完成。决议登记 CLOSE
  必须先 fsync，之后才能释放回收阻挡。迟到的决议必须匹配原有全局事务身份。
- 页面变更和回收凭据先持久化、复制。副本在凭据处完成清理和检查点，再处理后续
  复用该号码的记录。复制去重使用项目已有分片流 plsn。
- 物理基线携带原样的 32 位发号和回收水位，并替换旧 clog；本地事务尚未闭合时
  不允许替换其基线。

旧原生 WAL 也可能含已经复用过的普通号码。恢复时按已有的 WAL 日志位置判断
该记录是否还适用于当前槽。`pg_shard_xid/<oid>.redo/<段号>` 按同一个 uint32
槽号寻址，记录日志字节位置及校验和；它不是发号水位、事务轮次或 clog 索引。
每次授权复用时只更新该批槽的恢复边界，避免跨零提交和部分批次互相覆盖。
原 clog 的 32 字节槽格式、32 位槽索引和元组头均保持原样。

## 已实际执行的验证

1. 编译正常的 32 位版本和仅供加速验证的短环版本，执行 C 算术边界测试。
2. 空测试表从 4294967283 起步，真实跨越 UINT32_MAX，确认新号为 3，旧活行
   依靠显式冻结保留；立即崩溃重启后结果不变。
3. 短环版本只缩短环的测试边界，C 类型仍为 uint32。持续多圈提交、中止和
   TOAST 读取，确认旧连接不会缓存旧判决。
4. 旧快照阻挡回收直至停发，解除后恢复；另一个分片仍可写。
5. 授权前中断、回收公布后中断，以及 PREPARED 已获终局但本地尚未闭合的
   阻挡和崩溃恢复。
6. 两副本持续回放多圈复用、持久回收凭据、堆/TOAST/索引逐字节对比。
7. 重跑已有 VACU 合约、P5 页面清理、P7 自动清理及复制回归。

测试种子只能写入独立实验环境中已经停止的空夹具，不修改真实数据或既有实验。

## 验证边界与升级

本地合约用独立 TSO/worker；副本测试用1协调+3 worker，复用147已有容器，
使用独立安装副本、数据目录和154xx端口。没有将本次特性部署到原9节点实验，
也没有验证真实32位号码空间连续运行多整圈的耗时场景：真实32位测试仅给空夹具
注入临近最大值的水位后跨界，多圈复用由同一uint32实现的短环构建加速验证。

新增的水位文件格式及物理基线控制记录要求各副本同时使用兼容版本；未验证混合
版本或在线滚动升级。生产构建默认32位；`SHARD_XID_RING_BITS=8`仅用于专用测试。
旧实验08:33发生的缺失LIKE源表DDL段错误尚未定因，本次验收不宣称修复该缺陷。
