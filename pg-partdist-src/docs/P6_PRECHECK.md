## 结论二：R-P4-20 根因**已于本次定案**，正文里的旧假说须标注作废

**定案（2026-09-02，证据链完整）**：副本的 shard 文件被**两条互不知情的 redo
流**写——parwal 回放盖 **leader 坐标系**的页面 LSN，本地 pg_wal 崩溃恢复用
**本地坐标系**的 LSN，而 PostgreSQL 拿 `PageGetLSN()` 当幂等键。其中
`xlogutils.c:388` 的 **FPI 分支无条件 `RestoreBlockImage`，前面没有任何 LSN
比较**，于是本地 WAL 里任何一条带 FPI、落在副本页上的记录，在崩溃恢复时会把
回放好的页**盖回旧镜像**；回放游标毫发无损，下一条记录要的 `offnum` 就越过了
页尾 ⇒ `PageGetMaxOffsetNumber(page)+1 < offnum` ⇒ PANIC。

**取证（worker4 `startup.log`，实测）**：

```
14:02:41  ← 最后一次本地 checkpoint（= 后来那次 redo 的起点）
14:03:30  pg_partdist replay: shard 659454 追平至 11    ← 回放正常，游标 11 已持久
14:03:33  received immediate shutdown request           ← 崩溃注入
14:03:35  redo starts at 0/C8FA800 … redo done          ← 本地崩溃恢复，区间覆盖 14:03:30
14:04:51  认领 shard 659454，游标从 11 起 → PANIC       ← 下一条记录当场炸（重复 5 次）
14:41:00  回收陈旧槽位/目录（关系已不存在）
```

**三条此前未被记下的事实**：

1. **现象描述有偏差**。文档记"游标从 0 起"，而 30 次 PANIC 与前一行认领日志
   逐条配对后，**最后 7 次的游标是 10 和 11**。R-P4-20 诊断块的触发条件是
   `if (ctx->applied_part_lsn == 0)`（`shard_replay.c:606`）——**那个精心埋的
   取证点一次都没为它们打过**。这正是 geometry 两周没被记下来的原因。
2. **OID 复用不是机制**。13 个出事 shard 的 OID（26873 → 659454）**严格单调
   递增**，无一重复。因此正文里挂在 R-P4-22 名下的"`relNumber` 代际校验"假说
   **解释不了已取证的这一例**：08-18 那次 locmap 配对成功、回放顺利追平到 11
   （说明 relNumber 是对上的），崩溃恢复之后才炸。**该假说须标注为已废弃**，
   不要在 P6 里照着实施。
3. **项目自己早有同机制的受控实验**。`replay_worker.c:1443` 注释（2026-08-04）：
   崩溃前盘面 `pd_lsn=0/A74EFD0 btm_root=1`，immediate 崩溃重启后
   `pd_lsn=0/81DF748 btm_root=0`，后者**落在建壳表的本地 WAL 区间内**。
   当时打中的是索引元页，这次打中的是堆页，**同一个机制**。
   §13 约束 12 已把它写死，并自认"**这不能根治**"。

**连带定案的第二个方向**：同一个根在**升主侧**的症状是 §11 步骤 4 所述——
"若本地位点低于页 LSN，新记录 LSN 小于页面现有 LSN，本地崩溃恢复时
`lsn <= PageGetLSN` 会**错误跳过新记录**，数据丢失"。而它依赖的
**补丁 0003 不存在**（`patches/README.md:30`：3 号位作废不复用）。
> **★ 后续（2026-09-04，T6.3b）**：这件事由**新编号 0010** 实装，3 号位仍作废不复用。本节保留当时的核查原貌。
**这是全项目唯一一条"静默丢数据"的开口**，其余都会以崩溃或不可见形式发声。

## 结论三：「全量套件零 FAIL」的口径**必须先裁定**，否则 T6.7 无法开工

实测 `tests/` 共 **29 套**，而 `run_p5_exit.sh` 只跑 **9 套**。剩下 20 套不是
"忘了加"，是**跑不到一起**：

**按目标容器分（实测各套件的 `CONTAINER` 默认值）**：

| 目标容器 | 套数 | 套件 |
|---|---|---|
| `pg-citus-tx2-container`（本环境） | **9** | 恰好就是出口 runner 的那 9 套 |
| `pg-citus-replay-container` | **7** | clog_hole_c4 / ddl_fileset_d1 / follower_replay_r1 / freeze_sync_d2 / lazy_replay_l1 / local_wal_conflict / txn_layer_r2 |
| `pg-citus-tx-container` | **4** | dtx_commit_marker_tx2 / dtx_replay_tx1 / fastpath_divergence_tx4 / promote_catchup_tx3 |
| `pg-partdist-raft4-container` | **1** | shard_identity_p0 |
| 无（**容器内运行**，直接用 `/work/pg-install/bin`） | **8** | bulk_insert_recovery / corrupt_segment_recovery / crash_recovery / demux_backlog_recovery / enospc_recovery / multi_table_isolation / segment_boundary_lsn / shard_auto_init |

**两个硬约束**：
- **三套 9 节点集群互斥**（replay / tx / tx2 不能同时起），因此"全量一次跑完"
  在单机上**物理不成立**，除非把 20 套全部改成能在 tx2 上跑；
- **两种执行模型并存**（21 套宿主机 `docker exec` + 8 套容器内），归一后的
  runner 必须同时驱动两种。

**须裁定的三个选项**（列出成本，不代做决定）：
- **(a) 全部收编到 tx2**：逐套核实夹具在 tx2 上成立。成本最高，但"全量零 FAIL"
  才有单一含义。
- **(b) 分环境门禁**：tx2 跑 9+，replay 环境跑 7，tx 环境跑 4，raft4 跑 1，
  容器内 8 套随任一环境。成本最低，但"全量零 FAIL"变成四份报告的合取，
  且每次出口要起停三套集群。
- **(c) 缩编**：把 replay/tx 时代已被 tx2 套件覆盖的部分显式退役。成本中等，
  但需逐套论证覆盖关系——**这是唯一能让门禁长期不腐化的选项**。

## 结论四：进门禁前有**两条已知红**，且其中一条与 §13 约束 13 同源

2026-08-21 P5 出口时用 `CONTAINER` 覆盖跑过两套 replay 时代套件（属尽力而为
的越界取样），结果：

- **`test_txn_layer_r2` 50/1** —— 唯一的红是 **R-P4-22**「本轮无 Raft 提案被
  丢弃（`ring_full_drops + quorum_drops`）实际=2 期望=0」，50 条功能断言全过。
  ★ **它与 §13 约束 13 同源**：环容量 `RAFT_LOG_CAPACITY = 128`，背压
  `wait_for_log_room`（`raft_consensus.c:1552`）超时（`propose_wait_ms` 默认
  10s）后**仍然 `return false` 丢弃**；而丢掉的若是 VACUUM 物理截断的 DATA，
  就是文档记的"**永久分叉，既无检测也无修复路径**"。**这不是计数器噪声，
  是分叉风险的唯一可观测出口。**
- **`test_follower_replay_r1` 46/4** —— 4 条全是 `_vm` fork 存在性（leader 有、
  follower 没有）。当时已论证与 MARKER 改动无关，并**明确记为"待在 replay
  环境复核的一项"**；该项至今未进任何台账。

**结论**：这两条必须在 T6.7 之前处置（修 / 判为环境噪声并写明判据 / 退役该
断言），否则"全量零 FAIL"从第一次跑就不可能成立。

> **★ 两条都已处置（2026-09-04）**：
> - `follower_replay_r1` 的 4 条 `_vm` → **R-P6-6，T6.8 修掉**。根因不是两个
>   原假设中的任何一个，而是回放侧 R-P4-8 的守卫把判据下在了 fork 粒度上，
>   自我维持地把 VM 记录全跳过了。判据收窄到 `MAIN_FORKNUM` 后 r1 46/4 → **58/0**
>   （多跑起来 12 条原本被静默跳过的比对）。
> - `txn_layer_r2` 的 R-P4-22 → **批次 #8 定性**：那条断言**结构上永远不可能过**
>   （本套件 [9] 故意拆多数派，必然产生 quorum_drop，它在断言自己造出来的东西）；
>   且丢弃计数在 8/3 之后已不等于无痕分叉（增量点注释自陈）。改成"额度"式判据
>   后 **51/0**，而**非预期**的丢弃照样抓得住。
>   约束 13 真正的分叉机制（物理截断不随回滚撤销）由批次 #8 补上**检测**面。
